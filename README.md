# Дашборд для трекинга арбитражных запусков

Внутренний инструмент: таблица офферов (Leon / 1xBet) со статусами
«активен» / «освоено» и историей статистики по дням, которая собирается
каждое утро автоматически.

## Стек

- **Next.js** (App Router) — и страницы, и серверная логика в одном проекте
- **Supabase** (Postgres) — база данных, без своего сервера
- **Vercel** — хостинг + ежедневный cron для сбора статистики

## Схема сбора статистики

Модуль `src/lib/connectors` — общий интерфейс `getStats(offer)`, под который
подключаются коннекторы конкретных партнёрок:

- `mock.ts` — заглушка со случайными данными (используется сейчас для обеих
  партнёрок, чтобы проверять остальной функционал)
- `leon.ts`, `onexbet.ts` — заготовки под реальные коннекторы, пока бросают
  ошибку «не подключён»
- `index.ts` — выбирает коннектор по полю `network` оффера

Когда появится доступ к реальным кабинетам, нужно реализовать `getStats` в
`leon.ts` / `onexbet.ts` и переключить на них `index.ts` — остального кода
это не коснётся.

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # заполнить реальными значениями
npm run dev
```

## Переменные окружения

См. `.env.example`. Задаются локально в `.env.local` (не коммитится) и в
настройках проекта на Vercel (Project Settings → Environment Variables).

## База данных

SQL-схема — в `supabase/schema.sql`. Выполнить один раз в Supabase:
Project → SQL Editor → New query → вставить содержимое файла → Run.

## Ежедневный сбор статистики

`vercel.json` регистрирует cron на `/api/cron/collect-stats` (по умолчанию
06:00 UTC — поправить `schedule` под нужный часовой пояс). Эндпоинт
проверяет заголовок `Authorization: Bearer $CRON_SECRET`, который Vercel
подставляет сам, если в проекте задана переменная `CRON_SECRET`.
